# 行囊

在手机浏览器里规划自己的行程：用高德搜索地点，按天排好顺序，在地图上画出当天路线，再一键打开高德导航。

数据只存在这台浏览器的 `localStorage` 里，没有后端，也不需要部署。适合在国内本地使用。

## 准备高德 Key

地图、地点搜索和路线规划使用[高德地图 JS API 2.0](https://lbs.amap.com/api/javascript-api-v2/summary)。请申请 **Web端(JS API)** 的 Key，不要用 Web服务、Android 或 iOS 的 Key。

1. 打开[高德开放平台控制台](https://console.amap.com/dev/key/app)，注册并登录。个人开发者即可。
2. 进入「应用管理」→「我的应用」，创建一个应用。
3. 在该应用下点击「添加 Key」。
4. 服务平台选择 **Web端(JS API)**。
5. 把要用到的域名加进 Key 的白名单。本机开发请加入：
   - `localhost`
   - `127.0.0.1`
6. 创建后复制 Key。
7. 在 Key 列表里打开该 Key 的设置，查看 **安全密钥**（JS 安全密钥 / `securityJsCode`）。2021 年 12 月 2 日之后申请的 Key，调用 JS API 时需要同时填写安全密钥，否则地图会报 `INVALID_USER_SCODE`。

## 本地运行

```bash
cp .env.example .env
```

编辑 `.env`：

```bash
VITE_AMAP_KEY=你的Web端JS_API_Key
VITE_AMAP_SECURITY_JS_CODE=你的安全密钥
```

不要把填了真实 Key 的 `.env` 提交进仓库。`.env.example` 里只有空变量名。

```bash
npm install
npm run dev
```

浏览器打开终端里显示的本地地址，默认是 <http://localhost:5173>。

手机和电脑在同一个 Wi-Fi 时，可以用终端里的 Network 地址，在手机浏览器打开。改完 `.env` 需要停掉 `npm run dev` 再重新运行，Vite 不会热更新环境变量。

常用命令：

```bash
npm run dev        # 本地开发
npm run typecheck  # 类型检查
npm test           # 行程切分、导航链接等单元测试
npm run build      # 产出 dist，可用 npm run preview 在本地预览
```

## 怎么用

1. **新建行程**。名称随便起，城市建议填写，例如「杭州」。之后搜索地点会优先这个城市；这个城市没有结果时，会再搜一次全国。
2. **加一天**。每天可以改名字，并选择驾车或步行。至少保留一天。
3. **搜索地点**。输入「西湖」「灵隐寺」这类名称，点结果就加到当前这一天。
4. **调整顺序**。用「上移」「下移」排当天的先后。行程有多天时，可以把某一站「移到」另一天。
5. **看地图**。手机上点底部「地图」。地点按顺序标号，两点及以上会向高德请求驾车或步行路线并画出来。规划失败时会改成直线，并写明原因。
6. **打开高德导航**。
   - 每一站的「导航」：第一站从当前位置出发，之后的站从上一个地点出发。
   - 「用高德导航本日」：打开这一天的起终点。驾车且不少于 3 站时，会带上中间一个途经点。
7. **导入名单**。首页或行程里都可以贴一份地点列表，搜索匹配后再生成多天行程。

行程保存在浏览器本地，键名是 `trip-plan-h5:v1`。清除站点数据、换浏览器或无痕模式，都不会带着原来的行程。本应用不会把行程发到自己的服务器；搜索和路线请求由浏览器直接发给高德。

## 导入规则

v1 用一套直接的规则，不重排你已经排好的顺序，除非你勾选「按距离就近重排」。

- 一行一个地点。行首的 `1.`、`1、` 或 `-` 会被去掉。
- 同一行如果用顿号、分号隔开，且每段都不长，会拆成多个地点。例如：`西湖、灵隐寺`。
- 用空行，或单独一行 `---`，把名单分成多天。
- 写 `第1天`、`第2天`、`第二天` 这类标题时，按标题分天。标题同一行后面的文字也会当成地点。
- 名单里没有天数时，可以选「每天大约几个地点」（默认 4 个），或「平均分成几天」。多出来的地点放在前面几天。
- 勾选就近重排时，保留第一个地点，后面每次接离当前点更近的一个，再按上面的规则切天。已经分组的名单只在每一天内部重排。

搜索后可以换高德返回的其他结果，或去掉匹配错的行，再确认导入。

## 导航链接的限制

高德 URI 一次最多带 **1 个途经点**，而且途经点只在驾车时有效。所以：

- 当天只有 2 个地点时，「导航本日」就是从第一站到第二站。
- 驾车且超过 2 站时，链接是第一站 → 最后一站，并带上中间那一站。
- 步行超过 2 站时，链接不含途经点。
- 地图上的路线仍然会按全部站点规划。想严格按顺序走，用每一站的「导航」。

`callnative=1` 会在手机上尝试打开高德 App。微信、QQ 内置浏览器经常拦这个跳转，请用 Safari、Chrome 或其他系统浏览器打开本页面。

## 遇到问题时

| 现象 | 可以检查 |
| --- | --- |
| 页面提示还没有 Key | `.env` 是否在项目根目录，变量名是否是 `VITE_AMAP_KEY`，改完后是否重启了 `npm run dev` |
| `INVALID_USER_KEY` | Key 是否选成了「Web端(JS API)」，有没有多空格 |
| `INVALID_USER_SCODE` | 是否填写了 `VITE_AMAP_SECURITY_JS_CODE` |
| 域名不在白名单 | 控制台白名单是否包含当前访问用的 `localhost`、`127.0.0.1` 或局域网 IP |
| 搜索没有结果 | 城市是否填得太窄；可以先留空再搜，或换一个更完整的名称 |
| 路线是直线 | Key 的 JS API 权限、网络，或当天站点是否相距过远；驾车单次请求最多 16 个途经点，更多站点会自动分段 |
| 点了导航没有打开 App | 换到系统浏览器，并确认手机已安装高德地图 |

## 技术说明

- Vite + Vue 3 + TypeScript，纯前端。
- 高德 JS API 2.0：`AMap.PlaceSearch` 搜索地点，`AMap.Driving` / `AMap.Walking` 规划路线。脚本只从高德在线加载，不会打包进本地。
- 行程结构是「行程 → 多天 → 当天地点」，出行方式按天保存。
- 地点坐标优先使用高德返回的入口坐标，方便路线接到可到达的位置。
